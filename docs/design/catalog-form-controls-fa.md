# اصلاح ورودی‌ها و فرم‌های وابسته به کاتالوگ

- استایل‌های سفارشی outline، ring و border ورودی‌ها حذف شدند. فرم‌های داخل کارت از variant استاندارد secondary در HeroUI استفاده می‌کنند.
- در ساخت و ویرایش کلاس، کاور و گالری با آپلودر و امکانات و تجهیزات با انتخاب‌گر جست‌وجویی مدیریت می‌شوند. داده‌های قبلی هنگام بازکردن ویرایش حفظ می‌شوند.
- تنظیمات اختیاری کلاس از اطلاعات اصلی و هزینه و برنامه جدا شده‌اند. ارسال فرم تا پایان آپلود غیرفعال است.
- تخصص مربی از کاتالوگ تخصص‌های ادمین و نوع همکاری از کاتالوگ جدید employment_types انتخاب می‌شود. قرارداد API موجود برای عنوان تخصص و نوع همکاری حفظ شده است.
- در اپلیکیشن، تخصص و هدف تمرین از کاتالوگ انتخاب می‌شوند؛ توضیح تخصص جداگانه قابل ویرایش است. شناسه تصویر سبک تمرینی در متن قابل ویرایش نمایش داده نمی‌شود.
- فیلترهای JSON بخش اکتشاف ادمین با انتخاب‌گرهای شهر، رشته، نوع باشگاه، دسته‌بندی، برچسب و گزینه‌های مخاطب و ارائه جایگزین شده‌اند. سایر فیلترهای ذخیره‌شده بدون تغییر حفظ می‌شوند.
- seed نوع همکاری شامل تمام‌وقت، پاره‌وقت، درصدی، جلسه‌ای و قراردادی است؛ ادمین می‌تواند گزینه‌ها را مدیریت کند. seed موجود تکرارپذیر است و داده قبلی را بازنویسی نمی‌کند.

بررسی ورودی‌های قابل ویرایش در هر سه فرانت انجام شد. شناسه‌های فقط‌خواندنیِ رسید و جزئیات مدیریتی، و شناسه‌های داخلی فرم یا payload، ورودی دستی رابطه نیستند.

اعتبارسنجی: ۲۳ تست بک‌اند منابع، ۹ سناریوی بیزینس (با اجرای دوبارهٔ سه سناریوی فرم پس از اصلاح انتخاب‌گر) و ۳ سناریوی پروفایل مربی پاس شدند. بررسی TypeScript برای هر سه فرانت، بک‌اند و بسته UI و lint فایل‌های تغییرکرده انجام شد. تست‌های فرم با API شبیه‌سازی‌شده اجرا می‌شوند؛ سلامت سرویس‌های واقعی پس از انتشار جداگانه بررسی می‌شود.
