# برنامه تست Internal Release اندروید

## اطلاعات دور اجرا

| فیلد                      | مقدار |
| ------------------------- | ----- |
| Version name / code       |       |
| Commit SHA                |       |
| AAB artifact              |       |
| API release               |       |
| دستگاه، Android و WebView |       |
| تست‌کننده و تاریخ         |       |

حداقل ماتریس پیشنهادی: یک دستگاه Android 7/8 نزدیک `minSdk=24`، یک دستگاه
Android 13 و یک دستگاه Android 15 یا جدیدتر. حداقل یک دور با اینترنت موبایل و
یک دور با Wi-Fi انجام شود.

## دروازه ورود به Internal testing

- [ ] CI شامل typecheck، lint، تست کامل backend، bootstrap و health-check سبز است.
- [ ] E2E مرورگر برای ورود، رزرو، پرداخت، لغو و حذف حساب سبز است.
- [ ] AAB با کلید release امضا شده و `versionCode` تکراری نیست.
- [ ] API عمومی HTTPS است؛ `/health/live` و `/health/ready` هر دو پاسخ موفق دارند.
- [ ] MongoDB، Redis، GCS، SMS، Firebase، نشان و Sentry با credential همان محیط
      preflight شده‌اند.
- [ ] Privacy، Terms، Support و Account deletion عمومی و بدون ورود باز می‌شوند.
- [ ] فرم Data Safety با dependencyها و تنظیمات همین AAB تطبیق داده شده است.

## سناریوهای اجباری روی دستگاه واقعی

| شناسه | سناریو                       | نتیجه مورد انتظار                                             | وضعیت/شاهد |
| ----- | ---------------------------- | ------------------------------------------------------------- | ---------- |
| IR-01 | نصب تمیز از Internal testing | splash کامل، بدون صفحه سفید، بدون cleartext                   |            |
| IR-02 | ورود با OTP واقعی            | SMS فقط یک‌بار، ورود موفق و نشست پایدار                       |            |
| IR-03 | رد و قبول اعلان              | اپ در هر دو حالت قابل استفاده؛ تنظیمات دقیق                   |            |
| IR-04 | رد و قبول مکان               | denied از offline/server جدا؛ پس از اجازه نقشه فعال           |            |
| IR-05 | کشف تا جزئیات و سانس         | اطلاعات و ظرفیت منطبق با backend                              |            |
| IR-06 | رزرو و پرداخت موفق           | رزرو paid، رسید و اعلان درون‌اپ/Push/SMS                      |            |
| IR-07 | پرداخت ناموفق یا بازگشت ناقص | duplicate رزرو/برداشت ایجاد نشود؛ امکان retry                 |            |
| IR-08 | لغو و بازپرداخت              | درصد/مبلغ policy، وضعیت refunded و ledger منطبق               |            |
| IR-09 | Force stop و بازکردن از Push | deep link به رکورد مجاز و صحیح                                |            |
| IR-10 | قطع شبکه، timeout و HTTP 500 | سه پیام متمایز و retry سالم                                   |            |
| IR-11 | داده خالی واقعی              | empty state بدون متن خطای شبکه                                |            |
| IR-12 | حذف حساب                     | logout فوری؛ refresh token قبلی 401؛ ورود به داده قبلی ناممکن |            |
| IR-13 | لینک‌های حقوقی از تنظیمات    | مرورگر امن و URL درست                                         |            |
| IR-14 | ارتقا از نسخه قبلی           | نشست/تنظیمات معتبر باقی بماند و crash رخ ندهد                 |            |
| IR-15 | RTL، فونت و keyboard         | برش متن/دکمه و پوشاندن input رخ ندهد                          |            |

## آزمون چرخه عمر اپ

- [ ] foreground، background، force stop و reboot برای اعلان بررسی شده است.
- [ ] rotation، battery saver، شبکه ضعیف و تغییر Wi-Fi/دیتا بررسی شده است.
- [ ] بازگشت از درگاه با success، failure، cancel و بازشدن دوباره callback تست شده است.
- [ ] یک درخواست رزرو/پرداخت تکراری با double tap رکورد یا برداشت تکراری نمی‌سازد.
- [ ] ساعت و timezone تهران در سانس، یادآور و تاریخچه یکسان است.

## مشاهده‌پذیری و تصمیم انتشار

- [ ] رویداد آزمایشی Sentry با release و environment درست دیده می‌شود و PII ندارد.
- [ ] logهای backend شامل secret، OTP، token و متن حساس نیستند.
- [ ] نرخ crash/ANR و خطاهای API برای حداقل ۲۴ ساعت دور داخلی بررسی شده است.
- [ ] هیچ مورد P0/P1 باز نیست؛ موارد P2 مالک و موعد مشخص دارند.
- [ ] تصمیم `GO / NO-GO`، نام تأییدکننده و لینک شواهد ثبت شده است.
